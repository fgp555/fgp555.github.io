design system

Guía de diseño — frankgp.com

Sistema visual "terminal / dev" extraído de index.html: fondo oscuro, acentos cian/verde/ámbar, tipografía monoespaciada para títulos y datos, Inter para texto de lectura. Úsalo como referencia al crear cualquier página nueva del dominio para mantener consistencia.

⚠ 404.html actualmente usa un sistema distinto (acento morado, fondo #0f1115, fuente system-ui). Pendiente migrarlo a estos tokens para que todo el sitio comparta un mismo lenguaje visual.

✓ uso de acentos

cian = enlaces/foco/hover principal · verde = estado "disponible"/CTA primario/éxito · ámbar = métricas destacadas o advertencias, con moderación.

✗ evitar

No introducir colores nuevos por página (como el morado de 404.html). No usar los tres acentos juntos en un mismo componente pequeño.

tokens

Modo claro / oscuro

Por defecto el sitio sigue el prefers-color-scheme del sistema. El botón .theme-toggle (arriba a la derecha de esta página) permite forzar un modo, guardado en localStorage. Toda la lógica vive en theme.css (los tokens claros/oscuros) y en un pequeño script por página.

Botón

Muestra luna en modo claro, sol en modo oscuro (icono del modo al que cambiarás). 
<button class="theme-toggle" aria-label="Cambiar tema claro/oscuro" aria-pressed="false">
  <svg class="icon-sun">…</svg>
  <svg class="icon-moon">…</svg>
</button>

aria-pressed refleja si el modo claro está activo (lo mantiene el script de abajo) — sin esto, un lector de pantalla no anuncia el estado actual del botón.

Script requerido en cada página nueva

1) Bloqueante en <head>, antes de cualquier estilo, para evitar parpadeo. 2) El handler de click, en cualquier parte después del botón. 

<script>
  (function () {
    var saved = localStorage.getItem("theme");
    if (saved === "light" || saved === "dark") {
      document.documentElement.setAttribute("data-theme", saved);
    }
  })();
</script>

<script>
  (function () {
    var btn = document.querySelector(".theme-toggle");
    var mql = matchMedia("(prefers-color-scheme: light)");

    function isLightActive() {
      var current = document.documentElement.getAttribute("data-theme");
      return current === "light" || (!current && mql.matches);
    }
    function syncAria() {
      btn.setAttribute("aria-pressed", String(isLightActive()));
    }

    syncAria();
    btn.addEventListener("click", function () {
      var next = isLightActive() ? "dark" : "light";
      document.documentElement.setAttribute("data-theme", next);
      localStorage.setItem("theme", next);
      syncAria();
    });
    mql.addEventListener("change", function () {
      if (!localStorage.getItem("theme")) syncAria();
    });
  })();
</script>

Tokens especiales de tema

  • --brand-cyan / --brand-green — valores fijos (no cambian con el tema). Úsalos solo para fondos sólidos de botones que llevan texto oscuro fijo encima (ej. .nav-cta, .btn-primary).
  • --cyan / --green / --amber — se oscurecen en modo claro para mantener contraste como texto/borde sobre el fondo de página.
  • --header-bg / --header-bg-strong — fondo translúcido de headers sticky, adaptado por tema.
  • --glow-1 / --glow-2 — color de los degradados decorativos de fondo (body::before).

✓ hacer

Usar --cyan/--green/--amber para texto, íconos y bordes. Usar --brand-* solo para fondos sólidos de botón.

✗ evitar

No usar --cyan/--green como fondo sólido con texto oscuro fijo — en modo claro son colores oscuros y el texto se vuelve ilegible.

checklist

Reglas al crear una página nueva

  1. Enlazar theme.css y components.css en el <head> — no redefinir colores ni componentes por página.
  2. Cargar las mismas fuentes (JetBrains Mono + Inter) con el mismo <link>.
  3. Títulos en --mono, texto de lectura en --sans.
  4. Contenedor .wrap a 1120px máx, secciones con padding vertical 74px.
  5. Reusar clases de components.css (.btn, .badge, .tag, .card, .terminal, .timeline) antes de inventar una nueva.
  6. Si necesitas un componente nuevo, agrégalo a components.css y documéntalo aquí mismo — no lo dejes solo en la página que lo usa.
  7. Respetar prefers-reduced-motion (ya viene resuelto en components.css).
  8. Antes de publicar, comparar visualmente contra index.html para confirmar consistencia.
